⚠ INTENTIONAL VULNERABILITY — BROKEN OBJECT LEVEL AUTHORIZATION
Endpoints GET /api/notes/{id}, PUT /api/notes/{id}, and DELETE /api/notes/{id} do not verify that the note belongs to the authenticated user. Any logged-in user can read, modify, or delete any note by guessing or knowing its ID. Use the tools below to demonstrate this — this is the traffic Noname Active Testing will flag.

HOW TO USE

QUICK START

  1. Click a demo account button on the login screen (or use the Login form). Seed data should already be loaded — if not, click "Seed demo users + notes" first.
  2. After login you land on My Notes — you'll see notes belonging to the account you logged in as.
  3. Click any note to view it. Use Edit to modify it or Delete to remove it.
  4. Click New Note in the sidebar or top right to create a note.
  5. Go to BOLA Lab in the sidebar to exploit the vulnerability directly from the UI.

BOLA VULNERABILITY DEMO

  1. Log in as alice. Note the IDs of her notes in My Notes.
  2. Logout and log in as bob.
  3. Go to BOLA Lab → Read Any Note By ID. Enter one of Alice's note IDs. Bob can read it — he shouldn't be able to.
  4. Use Overwrite to replace Alice's note content as Bob.
  5. Log back in as Alice — she now sees Bob's tampered content.
  6. Use Enumerate to walk a range of IDs and discover all readable notes regardless of owner.

NONAME / ACTIVE TESTING INTEGRATION

  1. Point Active Testing at http://192.168.1.98:8000/openapi.json as the API spec.
  2. Configure multi-user auth with the four demo accounts above.
  3. Run the normal traffic script from the server first to establish a baseline:
    python3 ~/notes-test/normal_traffic.py --base-url http://192.168.1.98:8000 --duration 120
  4. Then run the exploit script:
    python3 ~/notes-test/exploit_bola.py --base-url http://192.168.1.98:8000 --aggressive
  5. Active Testing should surface a BOLA finding on the /api/notes/{id} endpoints.

FIX THE BOLA (Jenkins exercise)

In app/main.py, add this check inside get_note, update_note, and delete_note:

if note.owner_id != current_user.id: raise HTTPException(status_code=403, detail="Not authorized")

Rebuild the container, re-run the exploit — BOLA Lab will show 403s and Active Testing should clear the finding.
